Mail Commander (mcm) - requirements
===================================

A console email client in C with ncurses. This file lists everything needed
to build mcm again from scratch: what it does, how it looks, how it behaves
and what it must never do. The README describes the same program for its
users.


1. General
----------

- Written in C (C11, POSIX), one program called `mcm`; its full name is
  Mail Commander, used where there is room (--version, the Windows window
  title, the README); mcm where space is needed (menu bar, command, paths).
- Called emsg up to 0.94 (since 0.991 its settings are no longer
  converted: only ~/.config/mcm and ~/.local/share/mcm are used). The
  master password check keeps its old additional data "emsg master
  password check" and plaintext "emsg", or existing stored passwords could
  not be unlocked.
- ncurses with wide characters (ncursesw) for windows, keys and mouse.
- OpenSSL (1.1.1 or 3.x) or LibreSSL for TLS, random numbers and password
  encryption; iconv for character sets.
- Runs on Linux, FreeBSD, OpenBSD, NetBSD and Windows 10/11 (console). Tested on
  Linux and OpenBSD 8.0; the Windows build under Wine.
- Fully usable from the keyboard; the mouse is optional.
- Smallest supported terminal: 80 x 25.
- On exit (ui_end) a terminal without an alternate screen (no rmcup, e.g.
  the Linux console, TERM=linux) is cleared in its own colors, so mcm's
  screen and background do not stay behind.
- Licence: GPLv3.
- Version number in src/mcm.h (MCM_VERSION). Every change request raises it
  by 0.001 since 0.95 (0.951, 0.952, ...; the changes after 0.95 were
  renumbered 0.951-0.957). It is shown in the menu bar, by `mcm -V`, in the help texts
  (@VERSION@) and in the User-Agent header (`mcm/VERSION (Mail Commander)`).


2. Security (never to be broken)
--------------------------------

- Nothing goes over the network unencrypted: IMAP only as IMAPS (TLS),
  POP3 as POP3S or with required STLS, SMTP with TLS or required STARTTLS.
  If a server cannot encrypt, mcm refuses to log in or send.
- TLS 1.2 or later. Server certificates are checked against the system's
  trusted certificates and the host name.
- Passwords are never taken from the command line or a URL (a password in a
  URL is refused).
- Passwords are stored only when the user chooses so, and only encrypted.
- The master password and decrypted passwords live only in memory and are
  overwritten when mcm exits. The master password is never stored.
- Config file, certificate file and saved unsent text are mode 0600.
- The MS-DOS version (planned) never stores passwords and keeps TLS session
  data in memory only (see 18).


3. Building
-----------

- GNU make, a C compiler (GCC or Clang), pkg-config and awk.
- One Makefile for Linux, FreeBSD, OpenBSD and NetBSD (`uname -s`), using
  pkg-config where it exists and each system's package location otherwise:
    Linux    pkg-config for ncursesw and openssl; iconv in libc.
    FreeBSD  /usr/local (ncurses package); OpenSSL and iconv in base.
    OpenBSD  base curses (ncurses 6.4) with -D_XOPEN_SOURCE_EXTENDED and
             -lcurses, base LibreSSL, -liconv from packages in /usr/local.
    NetBSD   ncursesw from pkgsrc in /usr/pkg (base curses lacks mouse and
             extended colors), -Wl,-R/usr/pkg/lib.
- Library flags can be overridden: CURSES_CFLAGS, CURSES_LIBS, SSL_CFLAGS,
  SSL_LIBS, ICONV_LIBS.
- Targets: all, install, uninstall, clean, win, dos-bench.
  `make install` puts mcm in $(PREFIX)/bin and the themes in
  $(PREFIX)/share/mcm/themes; PREFIX defaults to /usr/local.
- Compatibility:
    ncurses before 6.1: init_extended_pair falls back to init_pair (256
      colors instead of 24-bit); no BUTTON5_PRESSED means no wheel down.
    LibreSSL has no scrypt: mcm has its own scrypt (RFC 7914, on top of
      PKCS5_PBKDF2_HMAC with SHA-256). It gives the same keys as OpenSSL's,
      so stored passwords can be moved between systems.
    Random numbers from RAND_bytes (no getrandom, rand or sprintf, which
      OpenBSD's linker warns about).
- Windows 10/11 (`make win`): cross-compiled on Linux with MinGW-w64
  (x86_64-w64-mingw32-gcc) into one static mcm.exe (-static: no DLLs but
  Windows' own). PDCurses 3.8 (wincon) is compiled from its source
  (PDCURSES=dir) into win/obj/libpdcurses.a with PDC_WIDE, PDC_FORCE_UTF8
  and PDC_RGB, the same defines mcm uses (compat.h); a mismatch in PDC_RGB
  swaps red and blue. OpenSSL, zlib and win-iconv from the static mingw64
  packages (WIN_LIBDIR); also -lpathcch -lbcrypt -lcrypt32 -lws2_32.
  Result in win/mcm/ (mcm.exe, themes/) and win/mcm.zip.
  src/compat.h is included first in every file (gcc -include);
  src/win32.c holds the replacements:
    files binary (_fmode), console code page UTF-8, Winsock started;
    HOME = %USERPROFILE%, XDG_CONFIG_HOME = %APPDATA%,
      XDG_DATA_HOME = %LOCALAPPDATA% when not set (so the rest of mcm uses
      its normal paths);
    rename replaces an existing file (MoveFileEx), realpath (_fullpath, '/'),
    pread, getline, strcasestr, memmem, asprintf, a wcwidth of 1 (PDCurses
    gives every character one cell), timegm (_mkgmtime), the computer name,
    mbox locking with LockFileEx, running a command and waiting (the
    external editor, default notepad).
  wchar_t is 16 bits: characters above U+FFFF are shown as U+FFFD; typed
  ones arrive as two UTF-16 halves and are joined (utf16_join) before they
  are stored as UTF-8. 256 colors: PDC_set_blink(FALSE) after start_color
  puts the console in VT mode.
  win/mcm.manifest (resource win/mcm.rc): active code page UTF-8, so file
  names in the ANSI calls are UTF-8, and long paths.
  net.c: Winsock (closesocket, millisecond timeouts, FormatMessage errors);
  the CA certificates come from the Windows ROOT store plus cacert.pem next
  to mcm.exe. ui.c: raw mode (Ctrl-C/Q/S are keys; Ctrl-C quits at the
  next key read), keypad Enter / + - * / as characters, resize_term after
  KEY_RESIZE, CTL_LEFT/CTL_RIGHT for word moves. Maildir names end in
  "!2,FLAGS" instead of ":2,FLAGS". Paths like C:\Mail on the command line.
- Help texts are plain text files in help/, turned into src/helptext.h by
  tools/txt2c.awk at build time. Lines starting with '#' are comments;
  @VERSION@ becomes the version:
    help/cmdline.txt  mcm --help / -h
    help/usage.txt    after a wrong option
    help/keys.txt     the F1 help window
    help/editor.txt   the editor's key line (one line)
- README.md: per operating system the packages to install and the exact
  build and install commands.


4. Command line
---------------

  mcm                      the only account, or choose one from a list
  mcm [options] [WHERE]

  -a NAME   use account NAME (a new one if unknown)
  -n        set up a new account (asks: IMAP, POP3 or local mail)
  -f WHERE  where the mail is (same as WHERE on its own)
  -s SERVER -p PORT -u USER
  -t THEME  theme name (~/.config/mcm/NAME.theme) or a path to a file
  -V, --version
  -h, --help

WHERE:
  imaps://[USER@]HOST[:PORT][/FOLDER]   port 993, folder INBOX by default
  pop3s://[USER@]HOST[:PORT]            port 995; 110 means STLS required
  /path, ~/path, ./path, file://, maildir:, mbox:   local mail

- The user may be an e-mail address: the last '@' ends it (%40 also works).
- An account with the same server and user (or path) is used; otherwise a new
  one is made and saved.
- Without arguments: the only account, last_account, or a list to choose from.


5. Configuration files
----------------------

~/.config/mcm/mcm.conf (mode 0600), key = value, one [account NAME]
section per account:

  theme = default
  wrap_width = 72            (20-998)
  check_mail = 60            seconds between new-mail checks when idle
                             (10-86400; 0 = only F5; C -> Check for new mail)
  message_wrap = 1           W: long message lines wrapped (1) or not (0)
  folders_width = 0          Folders: % of the screen, 0 = 25 % but at most
                             35 columns (0.994; 25, the old default, = 0)
  list_width = 45            percent (with three or four columns: of what is left)
  accounts_width = 0         Accounts: % of the screen, 0 = 25 columns (0.994;
                             15, the old default, counts as 0)
  editor =                   when $VISUAL/$EDITOR are not set (empty: vi)
  pdf_viewer =               PDF attachments (empty: xdg-open)
  html_viewer =              http/https/ftp links (empty: xdg-open)
  pdf_viewer_console =       the same without X/Wayland (empty: fbpdf,
  html_viewer_console =        jfbview, fbgs, pdftotext|less; w3m, lynx ...)
  last_account = Work
  master_check = enc1$...    the word "emsg" encrypted with the master password

  [account Work]
  type = imap | pop3 | local
  full_name, server, port, user, path, address
  smtp_server, smtp_port, smtp_user, smtp_login, smtp_security = tls | starttls,
  smtp_password, store_password = yes | no (no = do not ask again;
  absent = ask), password = enc1$...

- A config from emsg 0.3 (the old name; no sections) is read as one account.
- ~/.config/mcm/certs: always-accepted certificates, `host port sha256`.
- ~/.config/mcm/NAME.theme: color themes (see 13).
- ~/.local/share/mcm/ACCOUNT/: local Sent/Drafts of POP3 accounts.
- ~/.local/share/mcm/unsent-DATE.txt: text saved on Ctrl-Q / Ctrl-C.


6. Accounts and login
---------------------

- A new account first asks the kind: IMAP, POP3 or Local.
- IMAP/POP3 login dialog: account name, full name, server, port, user,
  password; the cursor starts on the first empty field.
- Local dialog: account name, full name, e-mail address (for From:) and the
  path; default path is the first of ~/Maildir, ~/Mail, ~/mail, $MAIL.
- A (Account) lists the accounts; the current one is marked *. Enter on it
  changes name, full name and stored password; Enter on another one or on
  "New account" switches to that account inside the running program
  (leave_account closes folders, messages, connection and the SMTP
  password; do_login; open_start_folder). The master password stays in
  memory, so it is asked once per run, at start. A cancelled or failed
  login goes back to the previous account; a new account that was not made
  is dropped.
- On startup INBOX is opened and the newest message is shown.


7. Certificates
---------------

- When the check fails (self-signed, expired, wrong name, unknown issuer)
  mcm shows subject, issuer, validity, the problem and the SHA-256
  fingerprint, with three buttons: Reject, Accept once (this session),
  Always accept (saved in ~/.config/mcm/certs).
- If a server with a saved certificate shows a different one, mcm warns
  that it has changed.
- Automatic reconnects accept only the certificate accepted at login.


8. Stored passwords (src/vault.c)
---------------------------------

- After the first successful login: Store encrypted / Not now (ask next
  time, the default) / Don't ask again.
- A master password is chosen once: typed twice, at least 8 characters.
  After that mcm asks for the master password at start instead of the
  account password; Esc skips it and shows the normal login.
- Key: scrypt(master, salt, N = 2^16, r = 8, p = 1) -> 256 bits; salt of 16
  random bytes, new for every stored value.
- Encryption: AES-256-GCM, random 12-byte nonce, 16-byte tag. The text
  "imap USER@SERVER" (or "smtp USER@SERVER") is the additional data, so a
  stored password does not decrypt when the server in the config is changed;
  mcm then says so and asks for the password.
- Format: enc1$LOG2N$R$P$SALT$NONCE$CIPHERTEXT+TAG (base64 parts).
- master_check makes a wrong master password known at once.
- C -> Delete all stored passwords removes them from every account together
  with master_check. An SMTP password is stored the same way when the
  account stores its password.


9. Mail sources (src/store.c is one interface for all of them)
--------------------------------------------------------------

IMAP (src/imap.c):
- IMAP4rev1 over TLS, LOGIN, LIST with RFC 6154 special-use attributes,
  SELECT, STATUS, UID FETCH of header blocks and flags, BODYSTRUCTURE,
  partial fetches BODY.PEEK[section]<off.len>, STORE flags, APPEND to Sent
  and Drafts.
- Folder names in modified UTF-7, shown decoded, nested by hierarchy.
- New mail and deletions from untagged responses (EXISTS, EXPUNGE, FETCH);
  NOOP every check_mail seconds (default 60) and on F5. The selection stays on the same message.
- On a dropped connection: reconnect once and repeat the command (password
  kept in memory for this).

POP3 (src/pop3.c):
- Port 995 and any port other than 110: TLS from the start. Port 110, or a
  plain-text greeting: STLS is required, otherwise no login.
- USER/PASS, LIST, UIDL, TOP for list headers, RETR when a message is
  opened. Nothing is ever deleted on the server.
- One INBOX from the server; Sent, Drafts and other folders are local
  Maildirs in ~/.local/share/mcm/NAME/ (or path =), made when first used.
- Seen/answered kept per UIDL in .mcm-pop3-state; ids no longer on the
  server are forgotten.
- A new session on F5 and every 5 minutes (a POP3 session only sees the
  mailbox as it was at login); kept alive in between.

Local (src/local.c):
- Maildir (cur/new/tmp) with Maildir++ subfolders (.Name, names in
  modified UTF-7). Flags in file names (S seen, R answered, F flagged,
  T deleted); reading moves a message from new/ to cur/.
- mbox: only read and appended to, fcntl locking, mboxrd >From quoting.
  Flags from Status/X-Status; messages read count as seen until exit.
- MH: numbered files, flags in the unseen/replied/flagged sequences of
  .mh_sequences (rewritten as a new file, other sequences kept); a saved
  message gets the next free number.
- Dovecot sdbox (0.990, read only; dbox.c): a root with mailboxes/ (no
  storage/: that is mdbox, refused in local_open) is walked like a directory
  (walk_dir, l->dbox set: names shown mUTF-7 decoded); a directory with
  dbox-Mails/ is an LF_SDBOX folder (subfolders beside dbox-Mails). Messages
  are the u.UID files (key = UID). dbox_locate: header line "2 M<hex> C..."
  gives the message header size; the header "\001\002N <8> <16 hex size>..\n"
  gives the size; the message follows. Flags (dbox_flags): dovecot.index
  (major 7, little-endian: header_size @4, record_size @8, compat @12,
  indexid @16, messages_count @32, log_file_seq @60, head offset @68;
  records uid u32 + flags u8), then the transaction log from the index's
  head offset (.log, or .log.2 from there then all of .log; no index: both
  whole): APPEND (8-byte uid+flags records), FLAG_UPDATE (uid1 uid2 add
  remove, 12 bytes); sizes in Dovecot's offset form (big-endian, 7 bits per
  byte, <<2). Index files in dbox-Mails/, else the mailbox directory.
  Changes: dbox-Mails mtime (messages), log mtime+size (flags). Seen set in
  mcm stays in memory (as mbox); append, remove, create, rename, delete
  refused. mail_compress output (gzip zstd bzip2 xz lz4 magic) is reported.
- A directory: every Maildir, mbox file and MH folder under it is a folder
  (subdirectories nest); $MAIL is INBOX when none is found.
- Sent and Drafts are listed before they exist; the first message saved
  there creates them, of the kind most folders there are.
- Changes by other programs are picked up on F5 and every minute.


10. Screen layout
-----------------

  mcm 0.996 Quit Mail Reply Forward Account Config F1=Menu  date time
  +- INBOX  3 msgs, 1 new --------------++- Message ---------------------+
  |A Weekly deals    Newsletter 261112.23:01|From    Newsletter <news@..>  ^
  |N Groesse aus.. Juergen M.. 261111.09:15|Subject Weekly deals          #
  |                                      <>Hello,                        v
  +-L-O-- TAB=Folder|Accounts  PgUp/PgDn -++-H-W-X-S-P-T---------- Spc=PgDn B=PgUp -+
   user@host  (Shift)Enter=Select message(s)  F5 Refresh  Q/^Q Quit

- Top line: menu bar with the context menu and the clock on the right.
  Hotkey letters in the HOTKEY color. A click on an item runs it. (Header
  and heX left the menu in 0.956: they are H and X on the message border.)
- ':' in the message window (msg_colon in msgwin.c): a command line on the
  bottom line. :e/:view/:vi/:vim -> view_in_editor(): the text as shown
  (whole message loaded) in a 0600 temp file (mkstemps; Windows
  %TEMP%\mcm-view-PID-N.txt), ui_run_editor(path, 1) (vi/vim/nvim/view get
  -R), then deleted. :q :q! :qa :x :wq -> quit. :w = S, :w FILE (O_EXCL,
  :w! O_TRUNC; ~ expanded), :hardcopy = P, :set [no]wrap / wrap! = W,
  :N :+N :-N (text lines, headers included) :$, :/text :?text (ASCII any
  case, wraps around, empty = last; A.srch), :h help. After a search
  A.hls = 1: draw_text_line paints every match (towlower compare on the
  tab-expanded wide line, within one display line) in CP_HIGHLIGHT, in
  every message, until :noh.
- ui_run_editor() (ui.c): ui_editor_cmd() ($VISUAL, $EDITOR, editor in
  mcm.conf = cfg_editor, else vi / notepad), run by ui_run_program():
  sh -c "exec $0 $2 \"$1\"" (Windows win_run), SIGINT ignored meanwhile;
  also used by the editor's :e.
- Viewers (0.992, attach.c): pdf_viewer / html_viewer in mcm.conf
  (cfg_pdf_viewer, cfg_html_viewer in main.c). open_with_viewer() sends a
  .pdf path to pdf_viewer, open_url() (links window) http/https/ftp links
  to html_viewer; empty: xdg-open / ShellExecute as before. run_viewer():
  console programs (console_program: w3m lynx links elinks less vi nano
  ...) or no $DISPLAY/$WAYLAND_DISPLAY -> ui_run_program (waits, in the
  terminal); else sh -c "exec $0 \"$1\"" in a detached grandchild.
  Windows: CreateProcess, not waited for. HTML attachments stay refused.
- Graphical or console (0.994, attach.c): graphical() = $DISPLAY or
  $WAYLAND_DISPLAY set (Windows: always). viewer_for('p'|'h') gives the
  program: pdf_viewer/html_viewer when graphical, else the _console
  settings, else the first in $PATH (in_path) of fbpdf jfbview fbgs, then
  "pdftotext -layout %s - | less"; w3m lynx elinks links links2. "" =
  xdg-open, NULL = none found (status line says which setting to set).
  A command with %s is a shell command line, %s -> "$1" (viewer_script in
  ui.c, also for ui_run_program). Without a desktop, xdg-open for other
  attachments runs in the terminal too (it was detached to /dev/null).
  mcm --programs prints the environment and the chosen programs.
- New mail (0.995, sync_changes): "HH:MM  New mail: N new messages in
  FOLDER", A.newmail = N (more mail adds up), drawn bold in
  CP_HIGHLIGHT (only the text) until set_status (any key) clears it.
- Status line: "(Shift)Enter=Select message(s)  F5 Refresh  Q/^Q Quit"
  with the focus on the email list, "Enter Open  F5 Refresh  Q/^Q Quit" on
  the folders and accounts (no F1, Tab, column or L/O hint: F1=Menu is in
  the menu bar, L, O and U on the list's border). With the focus on the
  message window it shows the ':' commands instead:
  ":e Vim  :/text Search  :N Line  :w Save  :q Quit".
- Selected messages (pick.c, 0.977): Enter in the list toggles the message
  under the cursor and moves down; Shift-Enter (ui_key_senter: CSI 13;2u,
  CSI 27;2;13~) selects from the anchor (the last Enter) to the cursor;
  Shift-Up/Down (KEY_SR/KEY_SF, PDCurses KEY_SUP/KEY_SDOWN) select while
  moving. The selection is a list of msg_t copies keyed by uid (msg_load()
  reads a header block that is not cached); cleared by Esc, opening a folder
  or switching account. Shown with '+' in CP_PICK (hotkey color on the
  background; the text color when that is the same or the terminal's own
  background). List title "..., N selected"; O on the list border at x+2,
  inverted while there is a selection; U at x+6 while there is something to
  undo (the filter bar starts at x+8).
- O: pick_window() covers rows 1..LINES-2: Flag (SAFD) Subject From
  Date (%Y-%m-%d %H:%M) Size (bytes / kB / MB, 1000-based), newest first.
  Under the list (0.980), after a ├─┤ line: "From: Name <addr>" and
  "Message-ID:" of the message under the cursor. msg_t carries addr and
  msgid (NULL when absent): IMAP from the ENVELOPE (from's mailbox@host, the
  10th field), local from the From: (mime_addr_email) and Message-ID headers.
  C copy / M move (ui_list_dialog of the account's folders, full paths,
  the open one left out), D delete = move to the trash folder (\Trash
  special-use, else Deleted Items / Trash / Deleted / Deleted Messages;
  IMAP: offer CREATE (+SUBSCRIBE) "Deleted Items", under INBOX<delim> when all
  folders are; local: a virtual Deleted Items like Sent/Drafts unless a
  Trash/Deleted folder exists); in the trash folder itself D asks and
  expunges. Uids are passed oldest first. Afterwards sync_changes() and
  cache_clear(), selection cleared.
- store_copy/move/delete/create: IMAP UID COPY, UID MOVE (CAPABILITY MOVE,
  asked once per connection), else COPY + STORE \Deleted + UID EXPUNGE
  (UIDPLUS); without UIDPLUS only the \Deleted mark (rc 1, no plain
  EXPUNGE). Uid sets compressed (1:3,7), commands split at ~900 chars.
  Local: local_copy (load_raw + local_append with \Seen \Answered
  \Flagged), local_remove (Maildir/MH unlink, MH replied/flagged sequences
  updated; POP3 DELE then pop3_reconnect = QUIT commits; mbox refused),
  then scan + merge so the removals come out of local_changes().
- Undo (U, 0.978): store.c keeps the last copy/move (kind, src, dst, n);
  store_delete (for good) and a failed action clear it, and it lives in the
  store, so switching account drops it. pick_undo() asks (ui_confirm),
  store_undo() works in dst (it leaves another folder selected), then
  reopen_folder() selects the open folder again, keeping filter and cursor.
  IMAP: before COPY/MOVE the Message-IDs (UID FETCH ENVELOPE) are noted;
  copy_start() resets the COPYUID list and, without UIDPLUS, notes STATUS
  UIDNEXT/UIDVALIDITY of dst. run_parts() catches [COPYUID v src dst]
  (untagged with MOVE, tagged with COPY) and [UIDVALIDITY v]. Undo: SELECT
  dst (UIDVALIDITY must match), candidates = the COPYUID uids or UID SEARCH
  UID next:* (>= next), keep those whose Message-ID is a noted one; every
  noted ID must match exactly as often as noted, else nothing is done. Then
  copy: STORE \Deleted + UID EXPUNGE; move: UID MOVE back (or COPY +
  expunge); a move that was only marked (no UIDPLUS): -FLAGS \Deleted on
  the originals, copies marked \Deleted (rc 1).
  Local: the append functions note what they wrote (l->wrote; mbox: size
  before, offsets after the padding, end); local_copy keeps the list.
  local_uncopy(back): Maildir copies found by name (or by the part before
  ":2," when renamed), MH by number (sequences cleared); with back the
  file is read and appended there with its (current Maildir) flags first;
  mbox: only when its size is still the noted end: each message read back
  (From_ and Status: lines and the closing blank line dropped, mboxrd
  quoting undone), then ftruncate to the size before. POP3 inbox as back:
  refused (DELE is final).
- Menu bar items are 2 columns apart (ui_menubar, ui_menu_hit); the clock
  keeps at least 2 columns from the last item (on 80 columns it moves to
  the right edge, so it still fits).
- No flicker: the F1 menu and dialogs paint the main screen under them
  with draw_bg (stdscr only, no refresh) and send everything with one
  refresh; draw() itself is paint + refresh.
- List bottom border: L at its left (bold, inverted while a filter is
  typed or applied; a click = L), the filter bar right of it.
- Message window bottom border: H W X S P T K at its left (bold; H W X
  inverted while on: H all headers, W wrapped lines, X hex dump, T plain
  text; S save, P print, K links and attachments, inverted when the
  message has any (open_has_att, open_has_links); a click = the key). W also switches H and X off. Then,
  with W off and a line wider than the window, a horizontal scroll bar
  (draw_hscrollbar, sbs[SB_HMSG]: arrows 8 columns, track a page, drag the
  thumb) up to the corner; otherwise the paging hint on the right.
- W on (message_wrap = 1, default): lines wrapped at the window width, at
  most 76 columns (WRAP_VIEW). W off: lines not wrapped; A.hoff is the
  first column shown, A.maxw the widest line. Toggling W keeps the text at
  the top of the window in view. Left/Right in e move the text 8 columns
  (HSTEP); Left at column 0 goes to the window on the left.
- Key list window (?, Help > Key list): a scroll bar in its right border when it does not fit
  (arrows, track, drag the thumb); the wheel scrolls it; a click elsewhere
  closes it.
- Menu window (menu.c, 0.985): F1 or F10 (Ctrl-M is not possible: the
  terminal sends it as CR, the same as Enter). One window at row 1,
  column 0, with six columns MCM, Account, Folders, Emaillist, Email,
  Help: the title (CP_HIGHLIGHT when it is the open column) and a line
  under it, then the items, alphabetical (case aside), with a hot letter
  (CP_HOTKEY, CP_HOTKEY_HL on the bar; written as the capital, 0.986:
  creaTe moVe reName edIt rEmove fiLter heX, '/' for "/ find"). A
  letter runs its item from any column, so each is used once: C Q A I
  E T D V N L O / F H X M P R S W. Lower-case items (select, the Help

Linux console) send Shift-Space as Space; the help says to use Ctrl-Space,
Alt-Space or Backspace there.

Ctrl-Q and Ctrl-C (either case) always quit, also in dialogs, the help, the
file picker and the editor, without questions:
- connections are closed without waiting for the server;

  (mode 0600) and its path is printed;

  Ctrl-S arrive) and restored at exit;
- Ctrl-C is a signal: it also stops a network wait (connect, TLS, a slow
  server). A second Ctrl-C leaves at once, restoring only the terminal;
- while :e runs an external editor, Ctrl-C belongs to that editor.

13. Themes
----------

- File ~/.config/mcm/NAME.theme, read at every start; NAME from -t or
  theme = (default "default"). If missing it is created from
  ./themes/NAME.theme, $(PREFIX)/share/mcm/themes/NAME.theme, or the
  built-in default colors.
- Keys: BACKGROUND, TEXT, HIGHLIGHTBG, HIGHLIGHTTXT, MENUBG, MENUTXT,
  HOTKEY, TITLEBG, TITLETXT, HEADERBG, HEADERTXT.
- Active window title (main screen and editor): pair CP_TITLE, TITLETXT on
  TITLEBG; unset (THEME_AUTO) = bright white (15) on HIGHLIGHTBG at 60%
  brightness (darker() in theme.c; cyan -> #007b7b, color 30 on 256-color
  terminals, cyan again on 8 colors). The selection bar keeps HIGHLIGHTBG.
- Message window header section: pair CP_HEADER, HEADERTXT on HEADERBG,
  for display lines with offset < mv.hdr_end (set by mv_render: the end of
  the summary or of all headers, without the blank line). Unset = TEXT on
  BACKGROUND lighter (lighter() in theme.c: each component *2+32,
  darkblue -> #2020a0, color 19 on 256 colors); if that fits to the
  same color as BACKGROUND (8 colors, default) the text is cyan instead.
- Colors: black red green yellow blue magenta cyan white, optional
  bright/light prefix, gray, darkgray, darkblue (#000040), navy, orange,
  default (the terminal's color), 0-255, #RRGGBB.
- 24-bit color where the terminal has it; otherwise the nearest of 256
  colors (darkblue -> 17). With TERM=xterm-256color and
  COLORTERM=truecolor/24bit the xterm-direct description is used, unless
  MCM_NO_DIRECT=1. There color values 0-7 are the terminal's palette, so
  fit() sends RGB #000000-#000007 as #010101 (Konsole showed #000000 as
  its palette black, dark gray).
- Shipped: default (PC Tools: white on dark blue, cyan bar, light gray
  menu, orange hotkeys), mc, dark, mono, eink-256color (black on white, grays
  only; black menus, gray bar so bold hotkeys stay readable), night-256color (dark
  red #870000 on #000000, no blue/white; chosen to map to 52/88/124/160 on
  256 colors; #000000 = 16, true black, as "black" is the terminal's color
  0, which many color schemes show as dark gray), amber-256color,
  green-256color (monochrome monitors), paper-256color (light). Black is
  #000000 in night, amber, green, eink and dark (background); default, mc
  and mono keep the palette names on purpose, so they follow the
  terminal's colors.

  (they need 256 colors or more); default, mc, dark and mono use the basic
  colors and keep their names. load_theme (account.c): when no NAME.theme

- Config -> Theme: theme_names() (theme.c) lists NAME.theme in the user's
  folder, ./themes and DATADIR/themes, sorted, no duplicates; the choice is
  loaded with load_theme() (account.c, also used at start), applied with
  theme_apply() + clear(), and saved as theme = in mcm.conf.
- Windows: win/mcm/mcm.exe depends on themes/*.theme, so a changed theme
  is copied and packed again.


14. Showing messages
--------------------

- Headers decoded: RFC 2047 encoded words, RFC 2231 parameters, any
  charset through iconv, shown as UTF-8 with correct wide characters.
- MIME: multipart, base64, quoted-printable. A plain-text part is shown
  when there is one; otherwise HTML or Markdown is converted to text.
  An empty plain-text alternative (at most 8 encoded octets / non-blank
  characters, e.g. some newsletters) counts as none: the HTML is shown
  (msgview.c walk and mime.c render_part).
  Attachments are listed with name, type and size, not downloaded.
- format=flowed (RFC 3676): soft breaks joined into paragraphs (per quote
  level), space-stuffing removed, DelSp=yes honoured, wrapped to the window.
- HTML to text (src/textconv.c):
    <style>, <script> and <head> left out; character references (named
      and numeric) become characters;
    paragraphs and line breaks; h1 underlined with =, h2 with -;
    bullet and numbered lists, indented when nested (ol start= kept);
    blockquote as "> "; <pre> exactly as written;
    links as "text [n]" with a "Links:" list of numbered addresses at the
      end (no number when the text is the address);
    images as [image: alt] (left out without alt);
    data tables (not nested, at least 2 rows and 2 columns, at most 10
      columns, cells at most 40 wide, at most 110 in total) in aligned
      columns, with a dashed line under a <th> header row; other tables as
      their text;
    at most one empty line in a row, no trailing spaces.
- Markdown (text/markdown, text/x-markdown): **bold**, *italic*, `code`
  lose their markers; # headings underlined (levels 1-2); links and images
  as with HTML; fenced (``` ~~~) and indented code kept as written,
  indented by 4; lists and quotes unchanged; backslash escapes.
- Markdown in text/plain (0.996, textconv.c md_detect): converted the same
  way when it uses two or more kinds of markup (# heading, two headings
  count as two, **bold**/__bold__, *italic*/_italic_, `code`, [text](url),
  ``` fence), quoted lines not counted. Not with T. Both paths: mime.c
  render_part and msgview.c render_leaf.
- Markdown styles (0.996): while mv_render runs (textconv_styles), md_to_text
  puts marker characters U+F8E0 + 2*style (+1 at the end) around bold,
  italic, ~~strike~~, code and heading text; ts_strip removes them from the
  rendered text and keeps spans (mv->sty) that draw_text_line draws: bold,
  A_ITALIC (else underline), U+0336 after each character for strike, code
  in CP_HEADER, headings bold in CP_PICK (level 3 "--> ", 4-6
  "-> "), bold in the text color (the user's wish; Konsole needs
  "Draw intense colors in bold font"). mv_body (replies), S, P and
  search see plain text. HTML has no styles yet (table widths).
- H (0.996, msgwin.c raw_view): the raw message (store_fetch_partial "",
  CRs removed, cut at the screen width) in a window over the whole screen;
  E opens it in the editor (edit_text, read only), Esc/H/Q close. W wraps long lines (max 76 columns) or not; X shows
  a hex dump of the raw message.
- The converters must survive any input (fuzzed) and be fast (800 KB in
  well under a second).


15a. Filter
-----------

- The email list's bottom border starts with L (inverted while filtering).
  L (from any window; the list gets the focus) opens a filter bar in that
  border: "Filter: text  Enter=Apply  Esc=Leave". Typed text appends,
  Backspace deletes a character, Ctrl-U all of it.
- Enter applies: the list shows only messages whose subject or sender
  contains the text, ignoring case. The title shows "FOLDER filtered  N of M msgs"; the
  border keeps "Filter: text  L=Edit  Esc=Leave"; the status line says how
  many match. Enter on empty text removes the filter.
- Esc leaves the filter, while typing or in the email list: the full list
  returns with the selection on the same message (with a filter applied,
  the selection goes to the same or nearest older matching message).
- Mouse: a click on the list's bottom border opens the bar; on Esc=Leave it
  ends the filter; while typing, a click elsewhere applies it.
- IMAP: SEARCH OR SUBJECT x FROM x on the server (CHARSET UTF-8 with
  literals for non-ASCII text). POP3/local: the headers are read and
  compared (lower-cased wide characters).
- The matching sequence numbers are kept (ascending); list row i is
  match nf-1-i. The header cache works on positions in that list, and
  headers of scattered matches are fetched with one FETCH of a sequence
  set (a,b,c:d). New mail/expunges re-run the search. Opening another
  folder ends the filter.


15. Memory and speed
--------------------

mcm keeps only what is on screen, so folder and message size do not limit
it (tested with a folder of 250,000 messages):
- Email list: headers fetched in blocks of 100 around the visible rows, at
  most 64 blocks kept, least recently used dropped first. Opening a folder
  fetches 100 headers; End fetches only the last block. While keys are
  still coming nothing is fetched; rows fill in when typing stops.
- Message: first the header and BODYSTRUCTURE, then the first 64 KB of each
  shown text part; the next block when scrolling reaches the end.
- Hex view: only a 16-64 KB window around the visible bytes.
- Display: text word-wrapped into an index of line offsets; characters are
  converted for the screen only for visible lines.


16. Writing mail (src/editor.c, src/compose.c)
----------------------------------------------

Editor (vim-like):
- M new, R reply (to Reply-To or the sender; In-Reply-To and References
  set; text quoted with "> "), F forward (original headers and text).
  R is reply-all (0.995): Cc = the original To + Cc without the To just
  made, the account's own address (login_address, an @ user) and
  doubles (compose_addrs_skip). Header window: "[X] " before Cc (XGUT
  columns in front of every name); a click on it or Ctrl-X on the Cc line
  (cc_clear, undoable) empties Cc and its continuation lines.
- E in the Drafts folder (0.995, send.c compose_draft): the draft fetched
  whole; To/Cc/Bcc (compose_addrs, else as written), Subject,
  In-Reply-To, References, the text (mime_render_body without its
  [Attachment: ...] lines), each attachment written with att_temp_file
  (the private attachment folder) and named in an Attach: line; From:
  this account's, else the draft's. Keep/Send as usual; the old draft is
  not removed.
  The text taken from the original is made valid UTF-8 first (utf8_clean):
  bytes that are not UTF-8 and C1 controls are read as Windows-1252, other
  control characters (CR, VT, ...) except tab are left out; otherwise the
  send check (valid UTF-8, no controls) would refuse it. HTML &#128;-&#159;
  are Windows-1252 too, as in HTML5.
  Showing: conv_to_utf8 uses utf8_repair for "utf-8", "us-ascii", no
  charset and charsets iconv does not know: valid UTF-8 as is, other bytes
  as Windows-1252, control characters kept. mime_decode_words converts
  adjacent encoded words of one charset together (a character split over
  two words) and repairs 8-bit header text outside encoded words.
- Two windows: header on top, message below. It opens in the header window;
  Tab goes to the message text; Esc (header or message) to command
  mode. Down on the last header line goes to the message, Up on the first
  message line to the header (also from command mode, which then edits).
- The header window is a form (pane_t.field): one row per line, "Name:"
  bold in a column as wide as the longest name (at most half the width),
  the field after it. Names cannot be edited: the cursor stays at or after
  hdr_min() (after "Name:" and its blanks; "Name:x" is stored as
  "Name: x"), Backspace stops there, Delete at the end does not join the
  next header, J does nothing there. A field wider than its room scrolls
  sideways with the cursor (pane hoff, only on the cursor line); other
  lines end in "…" when cut. Enter on Subject: to the message; on another
  line: a new empty line below; on an empty line: the next line (after the
  last: the message). A new line has no name yet and is edited from the
  left; typing its ':' makes it "Name: " and fixes the name.
- While the header or the message is edited the menu bar shows
  Esc=leaveEdit EdIt Send Keep Header Wrap aTtach Open for the mouse; a click
  leaves editing and runs the command (Esc=leaveEdit goes to command mode). The status line shows the
  mode, its keys and Ln/Col.
- A mouse click anywhere in the header or message window (text, empty part,
  frame) makes it the window being edited; below the text the cursor goes
  to the last line. The mouse button release must not clear a message.
- Command mode menu: EdIt Send Keep Header Wrap aTtach Open.
    E / I (i a A o)     edit again
    S                   send (confirm recipients first)
    K                   keep: save in Drafts and close
    H                   header window
    W                   wrap while typing on/off
    T                   attach a file
    O                   open a text file (open_file): an email message
                        (is_message: header lines, an empty line, one of
                        From/To/Subject/Date/Message-ID; mbox "From "
                        skipped) while To, Cc, Bcc and Subject are all
                        empty: those four (decoded) to the header, the
                        body (mime_render_body) to the message. Else the
                        whole file (utf8_clean) to the message. Text goes
                        into an empty message, or below the cursor line.
                        No NUL bytes, 16 MB at most. u undoes it.
                        (vim's O, line above, is not available.)
    gq                  re-wrap the paragraph at the wrap width
    yy Y dd p P x D J u yank, delete, put, delete char, delete to end,
                        join, undo
    arrows, Ctrl-Left/Right (word), b, PgUp PgDn, 0 $, gg G, Ctrl-F/B
    :q :q! :w :x :e :N  quit, quit without asking, keep, send,
                        $VISUAL/$EDITOR, go to line N
    Q, Esc              leave, back to the email list (focus on the list):
                        Continue editing / Keep as draft / Discard when
                        changed; Esc after d y g Z only cancels that
  Menu letters work in both cases (vim's h j k l w are not used).
- Template: From: Full Name <addr>, To:, Cc:, Bcc:, Subject:, Date: (filled
  in; replaced by the send time if unchanged), for a reply In-Reply-To: and
  References:; an empty line, then the text.
- The header window shows only To, Cc, Bcc, Subject and Attach: lines
  (continuation lines follow their header). The other header lines (From,
  Date, In-Reply-To, References) are kept hidden, unchanged, and sent; :e
  shows the whole text in the external editor. Header lines the writer adds
  stay visible. A header error in a hidden header is only reported.
  An empty From: (local account without address) is shown, and the cursor
  starts on it (shown_header() in editor.c, start = 0 in compose_start).
- Wrap: wrap width 72 by default (C -> Wrap width, or wrap_width).
  On for a new message, off for reply and forward. The last word that does
  not fit moves to the next line and the rest of the paragraph re-wraps.
  Quoted lines (>) and too long words are not broken.
- The menu item names the action: "unWrap" (hotkey W) while wrapping is
  on, "Wrap" while it is off; never inverted. unWrap (bp.nowrap): one row per line, all lines scrolled by
  bp.hoff; the cursor is kept 8 columns (hmargin) from the left and right
  edge. A horizontal scroll bar (hbar_t) on the message window's bottom
  border when the widest line (+1 for the cursor) does not fit: arrows 8
  columns, track a page, thumb dragged; afterwards the cursor is moved
  into the visible part.

Attachments:
- T opens a file browser (Enter opens a folder, ../ goes up, Enter on a
  file attaches it; first line "Type a path" for any path, also hidden
  files). Each file is an "Attach: path" header line (~ = home), which can
  also be typed or deleted by hand. Not sent as a header.
- Files are read at send/keep time, 100 MB at most together; the send
  confirmation shows their number and size.
- multipart/mixed: the text part, then each file base64 with a type by
  extension (otherwise application/octet-stream) and
  Content-Disposition: attachment; long or non-ASCII names per RFC 2231.

Header checks before sending (an error opens the header window on that
line):
- From, To, Cc, Bcc, Reply-To, Sender: RFC 5322 address lists (names,
  quoted names, groups; group syntax or several addresses in From only with
  Sender, RFC 6854). Local part at most 64 octets; valid domain labels or
  an address literal. At least one recipient.
- Date: valid RFC 5322 date-time, day of week checked.
- Message-ID, In-Reply-To, References: <left@right>.
- Subject may be empty (the confirmation mentions it).
- Each header only once; MIME-Version, Content-* and User-Agent are set by
  mcm; other headers are passed on.

The message that goes out:
- Date, Message-ID (random, at the From domain) and User-Agent: mcm/VER.
- Bcc left out of the sent header, kept in the Sent copy.
- Headers folded at 78, never over 998 characters.
- Non-ASCII names and subjects as RFC 2047 encoded words; a non-ASCII
  address: UTF-8 headers (RFC 6532) with SMTPUTF8 when the server has it.
- Body text/plain; format=flowed, us-ascii or utf-8: soft breaks keep a
  trailing space, Enter is a hard break (trailing spaces removed), lines
  starting with a space or "From " are space-stuffed, "-- " kept. 7bit;
  8bit with 8BITMIME, otherwise quoted-printable (also for lines over 998).
- A reply to a flowed message re-quotes it as flowed (one more > per
  paragraph, wrapped at 72 with soft breaks); other quotes line by line.
- After sending: a copy in Sent (RFC 6154 \Sent or a usual name); the
  replied message gets \Answered.


17. Sending (src/smtp.c)
------------------------

- From: the login if it is an address, else login@domain with the domain
  being the IMAP server without imap./imaps./mail.; the confirmation warns
  when From was changed to another address.
- Defaults: server smtp.<domain> (or the IMAP server), port 587, same user
  and password. C -> Outgoing mail changes these, remembered per login.
- 587: STARTTLS required (RFC 3207). 465: TLS from the start (RFC 8314);
  another TLS port with smtp_security = tls.
- EHLO (HELO as fallback) with the host name or an address literal; SIZE,
  8BITMIME, SMTPUTF8, AUTH PLAIN/LOGIN; dot-stuffing; CRLF; RFC 5321
  timeouts. If one recipient is refused nothing is sent and that address is
  shown. Certificates checked as for IMAP.
- Local accounts send with their SMTP settings; without a stored password
  mcm asks for one.

PGP (src/pgp.c, 0.995): through the gpg program (GnuPG, Gpg4win), per
account: pgp = no / yes / sign / encrypt / sign encrypt (what the PGP:
line of new mail says), pgp_key = the signing key (default the address);
A -> Enter on the current account changes both.
- gpg runs with --batch --pinentry-mode loopback --status-file; data in
  files in the private attachment folder (removed right away), the
  passphrase only on gpg's stdin (fork/exec, on Windows CreateProcess with
  a pipe; no shell). NEED_PASSPHRASE: mcm's dialog, then again with
  --passphrase-fd 0; a wrong one (BAD_PASSPHRASE, or ERROR/FAILURE with
  error code 11 in gpg 2.4) is asked again, Esc gives up.
- Reading (msgview.c, hooks mv_pgp set in load_selected): a top-level
  multipart/signed is loaded whole (mv_raw, up to 64 MB), part 1 with CRLF
  line ends and the signature go to gpg --verify; multipart/encrypted:
  part 2 to gpg --decrypt, and the result replaces the message: hdr = its
  header without Content-* + the decrypted entity's header, the fallback
  leaf its body (root NULL), so rendering, T, K (mv_raw) work on it;
  signed inside (RFC 3156 6.1) is checked too. The note goes under the
  header summary: "[PGP: ...]". Inline BEGIN PGP MESSAGE / SIGNED MESSAGE
  blocks in a completely loaded text part: gpg --decrypt once per block
  (mv->pgp_blk), the block replaced by "[PGP: note]" and its text when
  rendering. application/pgp-signature and pgp-encrypted parts are
  neither shown nor listed (nor @ in the list).
- Writing: PGP: line in the header (shown in the header window; parsed by
  compose_pgp_parse). compose_build makes the body entity once, then
  o->pgp (send.c pgp_cb -> pgp_wrap) turns it into multipart/signed
  (detached signature, micalg from SIG_CREATED; text forced to
  quoted-printable when it is not plain 7bit without trailing spaces) or
  multipart/encrypted (--armor --encrypt --trust-model always, yourself +
  To + Cc as --recipient, Bcc as --hidden-recipient; with sign: one
  OpenPGP message). Done before connecting to SMTP (errors at once:
  INV_RECP -> "no usable key for ..."). Drafts are not encrypted; they
  keep the line as X-Mcm-PGP, which E turns back into PGP:. A reply to an
  encrypted message gets encrypt in its PGP: line.


18. MS-DOS (planned) and the benchmark
--------------------------------------

The planned DOS version, for 8088/8086 PCs and up under MS-DOS or FreeDOS:
- IMAPS only; no POP3, local mail or plain IMAP.
- No stored passwords: asked at every start, kept in memory only.
- TLS session data in memory only (saved TLS 1.2 session data would let
  someone decrypt the next session, including the password). A reconnect
  within one run may resume the session.
- Server certificates are saved; later logins skip the chain check but
  still check the server's signature.
- Open Watcom (16-bit, large model, 8086 instructions), BearSSL 0.6
  patched for 16-bit int, mTCP for the network.

Already there: a TLS benchmark in dos/ (bench.c, vectors.h with known-answer
tests, bearssl-0.6-16bit.patch). `make dos-bench WATCOM=... BEARSSL=...`
builds:
- BENCH.EXE: 16-bit, i15/m15 arithmetic, any PC from the 8088 up;
- BENCH32.EXE: 32-bit (wcl386, DOS/32A extender, i31/m31, -fpc so no 387
  is needed), 386 and up.
`BENCH FAST` times X25519, ECDH and ECDSA P-256/P-384, RSA-2048/4096,
SHA-256, ChaCha20-Poly1305 and AES-GCM and writes RESULT.TXT. The README
holds the results measured in 86Box (8088, V20, 386DX-33 16 and 32 bit) and
the login times calculated from them.

20. Order of building (as it was done)
--------------------------------------

 1. Login to an IMAPS server
 2. Folder structure
 3. Messages of the selected folder (default INBOX)
 4. List with subject, from, date YYMMDD.HH:MM
 5. Show the latest message
 6. Vim-like editor and sending over SMTP
 7. Accounts, full name, encrypted stored passwords
 8. POP3 and local mailboxes (Maildir, mbox, MH)
 9. Attachments when writing
10. HTML and Markdown as text, mouse selection and wheel, portability to
    the BSDs, MS-DOS study

11. Open drafts again, save received attachments, reply-all, new-mail
    notice; PGP (0.995); Markdown in plain text, new-mail notice in
    black or white; Markdown bold, italic, strike, code (0.996)

12. make test: unit tests and a fuzz test of the parsers (0.996). They
    found two bugs: quoted-printable attachments lost their last byte when
    they did not end in a line break, and settings in an unknown
    [section] of mcm.conf made a nameless extra account.
    Hardening: stack protector, clash and CF protection, FORTIFY=3, PIE,
    full RELRO (HARDEN=0: off); Windows ASLR/DEP; make SANITIZE=1 for mcm
    itself; links get " encoded as %22 (one argument on Windows).
    One text pipeline: mime_text_part (mime.c) is used by both mime_render

    a hook (inline PGP, msgview.c), format=flowed, md_detect, invisible
    characters; T: as sent. Also shared: mime_alt_choose (which part of a
    multipart/alternative), mime_att_line ("[Attachment: ...]"),

    make static: tools/build-static.sh in an Alpine container: musl,
